## 1. Gladiator07/JARVIS — 670★, DEAD (last real commits 2022), MIT

- **Voice stack:** wake = none (post-STT phrase list) · STT = SpeechRecognition → Google Web Speech API (`en-in`) · TTS = pyttsx3 (SAPI5 voice 0) · brain = none (regex if/elif).
- **HOW IT ACTUALLY WORKS (inside):** `main.py:MainThread.TaskExecution()` → `startup()` canned speech → infinite loop: `Jarvis/__init__.py:JarvisAssistant.mic_input()` opens `sr.Microphone`, sets a **hardcoded `r.energy_threshold = 4000`** (no ambient-noise calibration — the call is commented out), `r.listen()` (no timeout/phrase limit), sends everything to Google STT. Result feeds a giant `if re.search(...) / elif "time" in command` chain in main.py. Wake handling = `command in GREETINGS` — a list of phrases ("hey jarvis", "wake up jarvis"...) matched *after* full cloud STT of every utterance.
- **Weaknesses (code truth):** `mic_input()` **recurses on recognition failure** (`command = self.mic_input()`) → unbounded stack growth in a noisy room; bare `except:` everywhere; `tts()` calls `engine.setProperty('rate', 175)` **after** `runAndWait()` — the rate never applies to the utterance just spoken (dead code); hardcoded personal email addresses in main.py; every sound the mic hears is shipped to Google (no local wake gate at all).
- **Stealable for v2:** NO — this is the tutorial archetype. Confirms only what v2 must never do (no wake gate, recursive retry).

## 2. isair/jarvis — 2,111★, ALIVE (commits daily), custom non-commercial license (ideas only)

- **Voice stack:** wake = deterministic text match on Whisper transcript (no audio wake model) · STT = faster-whisper (local) · TTS = Piper (exact-duration aware) · brain = Ollama local LLM (separate small "intent judge" model + main chat model).
- **HOW IT ACTUALLY WORKS (inside):**
  - **Audio loop** (`src/jarvis/listening/listener.py`, ~3,000-line monolith): mic frames resampled to **16 kHz PCM16**, Silero-style VAD `self._vad.is_speech()` per frame; utterance endpointing = **800 ms of silence** (`endpoint_silence_ms` default) counted in frames, plus a max-frames cap. A hallucination guard drops segments whose no-speech probability is too high. Hidden trick: on silence it **feeds low-amplitude noise, not zeros**, because pure silence trips faster-whisper's no-speech short-circuit and skips decoding entirely (comments at listener.py ~L1934/L2150).
  - **Wake detection** (`listening/wake_detection.py`, read fully): zero LLM. Configured names + aliases matched by a Unicode-aware regex at word boundaries (NFC normalisation); fallback = `difflib.SequenceMatcher` fuzzy match on single tokens with **ratio ≥ 0.78**. Stop commands: exact-in-normalised-text, or fuzzy **≥ 0.80** for ≤2-word inputs. Echo discrimination: if heard text ≈ a stop command it's a command even inside TTS text; otherwise `heard in spoken` ⇒ echo.
  - **Echo system** (`listening/echo_detection.py`, 27 KB): `EchoDetector(echo_tolerance=0.3, energy_spike_threshold=2.0)`. Tracks TTS start/finish and the **exact synthesised duration from Piper**, deriving true words/sec to map heard words back onto the spoken timeline; RapidFuzz `partial_ratio` + `token_set_ratio`, similarity threshold **85** (90 for extended search; 70 inside the hot window). **Echo salvage:** `cleanup_leading_echo_during_tts()` strips only the leading echo words from a mixed segment so a barge-in ("stop — actually what's the weather") survives as clean user speech; the transcript buffer's `is_during_tts` flag is then cleared so the judge doesn't skip it.
  - **Ambient transcript** (`listening/transcript_buffer.py`, read fully): thread-safe rolling buffer (default retention 120 s in code despite a "5 minutes" docstring — docs/code disagree), segments carry timestamps, energy, `is_during_tts`, and a `processed` flag so the judge never re-extracts the same query twice.
  - **Intent judge** (`listening/intent_judge.py`): small local LLM decides "addressed to me / stop / ignore", temperature **0.0**, `num_ctx` 8192, Ollama `keep_alive` to avoid cold-reload tax. Hard-won constant: `max_tokens` **1500** — comment documents that 500 truncated reasoning models mid-JSON and lost whole judgments. 30 s error cooldown; JSON extracted by brace-matching helper.
  - **Hot window:** after answering, a **3.0 s** window (`hot_window_seconds`) where follow-up speech without a wake word is accepted, gated by the echo checks above.
- **Weaknesses:** listener.py is a ~130 KB single file — the state machine is powerful but nearly unmaintainable; the design **always transcribes everything** (privacy/energy cost of the ambient transcript); fuzzy wake threshold 0.78 will false-positive on similar names; requires a GPU-class Whisper + two local models resident.
- **Stealable for v2:** YES — three direct steals: (1) deterministic wake/stop matching with fuzzy ratios + echo-aware stop priority (pure stdlib `difflib`/`re`/`unicodedata`); (2) echo salvage by TTS-timeline word mapping using exact TTS duration; (3) transcript-buffer segment flags (`is_during_tts`, `processed`) + the max_tokens headroom lesson for any judge-style JSON call.

## 3. huggingface/speech-to-speech — 13,516★, ALIVE, Apache-2.0

- **Voice stack:** wake = none (server pipeline) · STT = pluggable (Whisper/FireRedASR/Parakeet…) · TTS = pluggable (Kokoro/ChatTTS…) · VAD = Silero + optional learned Smart-Turn.
- **HOW IT ACTUALLY WORKS (inside):** a chain of **threaded handlers connected by queues** (`baseHandler.py:BaseHandler` — each stage owns `queue_in`/`queue_out`, a `stop_event`, and a `PIPELINE_END` sentinel to avoid queue deadlock; `SESSION_END` is a soft per-session reset that doesn't kill threads). Flow: audio → `VAD/vad_handler.py:VADHandler` → STT → LLM (token streaming) → TTS → audio out, with control messages flowing alongside data. The VAD wraps Silero iterators with defaults `min_silence_ms=64`, `speech_pad_ms=30`, and a **Smart-Turn end-of-turn model at threshold 0.5** — a learned classifier decides "is the user actually done?" instead of silence alone. Sub-threshold speech bursts are held in a `_PendingShortSegment` stitcher so fragments can't sum past `min_speech_ms` and trigger a phantom turn; streaming STT receives pre-speech padding prepended so word onsets aren't clipped. Threshold and silence duration are **hot-updatable at runtime** via config messages (`_apply_runtime_turn_detection`). TTS inputs carry a *prefetch transaction*: speculative next-turn synthesis is discarded unless the pipeline claims it — speculative work never reaches the speakers unclaimed.
- **Weaknesses:** heavyweight (torch everywhere, GPU-assumed); enormous config surface; it's a framework for builders, not an assistant.
- **Stealable for v2:** YES (architecture, Apache-2.0) — (1) queue-of-stages with explicit END/SESSION_END sentinels maps 1:1 onto v2's 8-stage voice graph and makes stage isolation testable; (2) "smart turn" idea in cheap form: after VAD endpoint, a 0-token heuristic (trailing conjunction/filler check) before committing the turn; (3) prefetch-claim pattern → v2 should never let speculative TTS audio reach the mixer unclaimed.

## 2. gia-guar/JARVIS-ChatGPT — 463 stars, DEAD (changelog ends 2023), MIT

TTS: **four-provider ladder** — ElevenLabs → IBM Watson TTS → **Coqui YourTTS zero-shot voice clone** (the actual Iron Man JARVIS voice, from one `jarvis_en.wav` reference) → pyttsx3. Requires copying hand-patched files into site-packages Whisper (`whisper_edits/`) — installation by surgery. Coqui TTS and Whisper-original are both unmaintained now.
- **Stealable for v2:** **Yes — two patterns.** (1) The **TTS fallback ladder with language-based routing**: detect reply language → pick provider/voice per language → on any provider failure, fall to the next rung, ending at a local offline voice. Exactly right for v2's cloud-keys → Piper/Kokoro ladder and Hinglish routing. (2) **Whisper language-prior filtering**: restrict `detect_language` argmax to the languages you actually support (en/hi) before decoding — a 5-line guard against wrong-language transcripts. The dual-stream VAD recorder (VAD at its own sample rate, decoupled from the capture rate) is also a clean trick if v2 ever records and VADs at mismatched rates.

Its clean `stop()` teardown order (processes → detector → stream → PortAudio terminate) is the right shutdown checklist.

  - **Thresholds & chunking:** Default `threshold=0.40` in the Python engine (clamped `set_threshold(0.3..0.95)`); README false-trigger tables are measured at `0.5` with a 40 ms sliding window.   - **5-layer anti-false-trigger (L1–L5)** — `DetectionLogic` defaults in the standalone port: `thr=0.5, cons_frames=5`; engine defaults ship with **only L1 on**:
    - **L1 (ON by default):** consecutive frames — need `cons_frames` (per-keyword, from `model_info.json`, default 2–3) frames above threshold for the *same* word, tolerating gaps of `MAX_GAP=2` frames.

    - **L3:** cooldown `1500 ms` (`set_cooldown` clamps ≥500 ms).
    - **L4:** burst detection — 3 triggers of the same word (prob >0.8 in the standalone port) within 3000 ms → `blocked = now + 5000 ms` suppression (anti feedback-loop).
    - **L5:** energy jump — compares current RMS against the minimum RMS in a pre-window 500–2000 ms before the candidate (needs ≥5 samples); standalone port uses an absolute delta `l5_delta=1200` plus a *post-speech confirmation*: wait `POST_DELAY=700 ms`, then require the RMS in the last `POST_TAIL=300 ms` to fall below `pre_min * RETURN_RATIO(2.5)` — i.e. real speech that *ends*, vs. continuous music/video. Engine version uses a ratio form (`l5_ratio=3.0`, clamped 2.0–8.0, plus absolute floors `preMin<50 and rms<80 → block`).
  - **Measured quality (README, bare model, layers off):** recall 90.3–100% (mean 98.8%, 20 keywords, held-out Azure TTS); *Hey Jarvis* optimized model 99.0% recall at 4.8 false triggers/hour on a 26.9 h hostile corpus (from 44.6/h before). **Hard-negative mining loop:** the trained model scans its own negative corpus, collects segments it wrongly scores high, and retrains on them ("R1" models) — −89% to −99.4% false triggers in one round with recall preserved. Adding only L1 (cons=2/3) cuts the flagship Chinese model further, 3.5 → 2.3 / 1.0 triggers/h.

The Python demo's 1-second callback window is a reference implementation, not a low-latency streaming design. L2/L4/L5 are off by default and the two Python implementations (engine-inline vs `detection_logic.py`) already disagree on constants (×2.0 vs ×3, ratio vs delta L5) — config drift across the 5 platform ports is a real risk. Baseline (R0) multi-keyword demos have *not* had false-trigger optimisation.
- **The one clever mechanism:** Shared-backbone multi-keyword heads at ~0.8 KB per extra keyword, bundled as a single loadable ZIP — one 135 KB model that wakes on "Hey Jarvis / Jarvis / Hi Jarvis" simultaneously.

- **HOW IT ACTUALLY WORKS (inside):** Cleanest small implementation in the batch (`src/openjarvis/speech/`). `wakeword.py:OpenWakeWordDetector.wait()` blocks reading 1280-sample (80 ms) blocks from a continuously-open mic and fires when `max(model.predict(samples).values()) >= threshold`, then `model.reset()` so one trigger can't double-fire; **any failure (not installed, model download fails) degrades to `PushToTalkDetector` with a printed warning instead of crashing** (`build_detector()`). `audio.py`: the mic stream is opened **once** for the session (re-opening PortAudio "costs a few hundred milliseconds and sometimes loses the first block"); a callback thread fills a `Queue(maxsize=200)` and *drops* blocks rather than blocking PortAudio's realtime thread; a pre-roll deque keeps `preroll_blocks=8` (640 ms) because "wake-word detection eats the first few hundred milliseconds… without it 'hey Jarvis, open Chrome' transcribes as 'pen Chrome'". `record_utterance()`: energy VAD that **calibrates to the room by tracking the noise floor continuously**, `sensitivity=2.5`× floor, `silence_ms=900` to end, `min_utterance_ms=400`, `max_seconds=20`, `start_timeout_s=6`. Session flow: wake → record → cloud STT → agent loop → **safety policy outside the model** (every tool declares `safe / caution / dangerous`; dangerous asks first by voice or keyboard; deletes go to the Recycle Bin; `C:\Windows`, Program Files and drive roots are hard-blocked before the tool runs; optional `safety.allowed_roots` allow-list; `--dry-run` declines all confirmations) → speak → **8-second follow-up window** without wake word ("stop" re-sleeps). README is candid about model choice: `gpt-oss-120b` over Llama-3.3-70B because Llama on Groq "intermittently emits tool calls as plain text" (`tool_use_failed`) — OpenJarvis retries those automatically.
- **Weaknesses:** No local STT at all — offline, it can wake and then do nothing useful. edge-tts is an unofficial free endpoint (breakage/ToS risk as the *primary* voice). Energy VAD admittedly weaker than Silero in loud rooms (the docstring says so). 5 stars / single-author — unproven in the wild.
- **The one clever mechanism:** Graceful-degradation discipline — every voice component has a designed fallback (wake→push-to-talk, edge-tts→pyttsx3, Groq→OpenAI) and a `jarvis doctor` command that checks keys/mic/wake/TTS up front.
- **Stealable for v2:** **Yes (MIT).** (1) The pre-roll + single-open-mic + drop-don't-block queue trio from `audio.py` — small, stdlib+numpy, directly applicable to v2's voice plugin. (2) The risk-tier safety policy enforced *outside* the prompt (safe/caution/dangerous + hard-blocked system paths + Recycle-Bin deletes) as a reference design for v2's gate — v2 has approvals already; this is the crispest open-source statement of the pattern. (3) The 8 s follow-up window constant matches v2's design intuition.

# ═══ TEAM 1 SYNTHESIS — 43 repos read at code level ═══

**Field state in one paragraph:** The tutorial long tail (SpeechRecognition→Google + pyttsx3 + if/elif) is still the majority pattern, and its failure modes repeat verbatim across continents: substring "wake words", recursive/blocking retries, per-utterance engine re-init, STT-as-wake-word with correction tables and hallucination blocklists papering over it. Real engineering concentrates in ~8 repos: isair (echo/intent discipline), ethanplusai (ack-based speech scheduling), eadmin2/jarvis_ai (voice-server reference), HF speech-to-speech (pipeline architecture), row-bot (mic/TTS gating), Voicute onnx-wakeword (wake models), Xiaozhi (sherpa-onnx KWS + AEC), Irene (plugin TTS discipline). Nobody in 43 repos does true acoustic echo cancellation except Xiaozhi's dedicated AEC engine; everyone else gates, mutes, or matches text.

## TOP 5 MECHANISMS (from code, ranked by value to v2)

1. **Echo salvage + ack-based echo model** (isair `echo_detection.py` + ethanplusai `speech.py`): map heard words onto the TTS timeline using the *exact synthesised duration* (RapidFuzz ≥85) and strip only the echo prefix so barge-ins survive; treat *unacked* playback chunks as still-live echo, relax the filter after ack + ~1 s grace, and keep `remaining_text()` = what was generated but never heard. Together these are the complete, principled version of v2's novel-word barge-in rule.
2. **Voicute multi-keyword wake package** (onnx-wakeword, MIT): one ~135 KB Causal-TCN ONNX wakes on {Hey Jarvis · Jarvis · Hello Jarvis} simultaneously (heads cost ~0.8 KB each), hardened by a 5-layer detection stack (consecutive frames w/ gap tolerance, peak/background ratio, cooldown, burst suppression, energy-jump + post-speech tail confirmation) and a hard-negative mining loop that cut false triggers ~90–99 % (Hey Jarvis R1: 99.0 % recall, 4.8 false/h on a 26.9 h hostile corpus).
3. **Intent-judge pattern** (isair): a small local LLM at temperature 0 deciding addressed/stop/ignore over a flagged rolling transcript (segments carry `is_during_tts` + `processed`), while wake/stop *detection* stays deterministic (regex + difflib fuzzy 0.78/0.80). Plus the scar: judge JSON calls need ~1500 max_tokens or reasoning models truncate mid-JSON and the judgment is lost.
4. **Interrupt-note + partial-transcript scheduling** (eadmin2/jarvis_ai): on barge-in, save the last *actually spoken* sentence and prefix it to the next turn's prompt ("your previous reply was cut off after you said: …"); live partials re-transcribed only on ≥1.2 s new audio, one task in flight, 30 s cap; per-turn timing JSONL makes latency bugs data.
5. **Learned end-of-turn + staged queue pipeline** (HF speech-to-speech): Silero VAD + a Smart-Turn classifier (threshold 0.5) instead of silence-only endpointing, short-burst stitching, and handlers chained by queues with explicit PIPELINE_END / SESSION_END sentinels and claim-gated speculative TTS prefetch.

## TOP 3 STEALS FOR JARVIS v2

1. **Adopt Voicute's Hey Jarvis multi-keyword model + L1/L3/L5 detection layers** — directly attacks v2's known gap (no bare-"Jarvis" model; hey_jarvis interim; the owner still owes ~50 training samples). One 135 KB ONNX gives {Jarvis · Hey Jarvis · Hello Jarvis} — matching the locked two-wake-word scheme (local vs cloud brain) — at <5 ms/frame on CPU, MIT engine. Benchmark against livekit-wakeword before committing; port the detection layers regardless of winner.
2. **Rebuild v2's echo/barge-in on the isair+ethanplusai model** — exact-duration TTS timeline mapping, echo salvage (strip prefix, keep the barge-in), per-chunk playback acks with an ack-floor lie-detector (ack can't predate the audio's own duration), unacked = live echo, `remaining_text()` feeding the utterance record. This is v2's "record what was spoken" rule implemented at production grade; re-implement from design (isair is custom-license, ethanplusai non-commercial — ideas only).
3. **The streaming speech-policy pack** — alts' clause-delimiter sentence cutting (`.?!;:` + dashes/parens, not just sentence ends) + ethanplusai's asymmetric first chunk (min 40 / max 160 chars) + eadmin2's `_clean_for_tts` as a pure function (strip think-blocks, elide code, flatten markdown, **redact secret-shaped strings before any cloud TTS**) + interrupt-note injection. Combined effect: first audio in <1 s, nothing unspeakable or secret ever reaches a TTS provider, and barge-ins stay conversationally coherent. All stdlib-shaped; fits Piper/Kokoro/Fish backends and the RTX 2060.

**Constants worth adopting as defaults (independently converged across repos):** 16 kHz mono everywhere · 1280-sample/80 ms frames for wake+Whisper paths · ~640 ms pre-roll · 0.8–1.5 s silence endpointing · 3–20 s follow-up windows (8 s is the modal value) · Whisper `small` CPU / `large-v3-turbo` CUDA split · canned phrases pre-synthesised at startup (kobold) · Whisper hallucination blocklist ("Thanks for watching!" class) as a 10-line output filter.
