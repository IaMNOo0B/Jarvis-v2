## 🏆 TOP 5 MECHANISMS (from code, ranked by steal-value for v2)

**1. Observation-bound actions: one-use `capture_id`** — trycua/cua, `libs/cua-driver/README.md` + `docs/perception-extension.md`. The driver's optional perception extension parses a retained screenshot into text/icon regions; **a region-derived pixel click must carry the same one-use `capture_id` as the observation it was derived from**. Stale or foreign observations cannot authorize actions — the driver enforces mechanically what prompt instructions only request. A read-only offline `perception parse` mode explicitly *cannot* authorize actions. Ports directly onto v2's `pc.observe` → `pc.click` pair: stamp every observation, require the stamp on coordinate actions, burn it after one use.

**2. Semantic pre-filtering of the control tree** — microsoft/UFO, `ufo/automator/ui_control/control_filter.py` + `inspector.py:UIABackendStrategy`. UFO walks the UIA tree with a property CacheRequest, embeds every control's name/type, and a ControlFilter (text / semantic-embedding / icon retriever variants) keeps only the top-k controls relevant to the current plan step before anything reaches the LLM. The full tree never enters the prompt. v2's UIA observation has no relevance filter — on dense windows (Explorer, Office) it will drown the model. A BM25/embedding top-k over control names is a small, stdlib-shaped addition.

**3. DVOC: iterative relative-offset grounding refinement** — Pomilon-Intelligence-Lab/DVOC, `PAPER.md`. Don't ask a weak VLM "where is the target?" — show it its own previous estimate as a **crosshair + 30px uncertainty circle** rendered on the screenshot and ask "how far off is the marker?" via `report_offset(dx, dy, confidence)`; apply corrections under exponential damping (α = 1.0, 0.5, 0.25…), stop when error < 30px with confidence ≥ 0.5 twice consecutively, abort on 3 non-decreasing errors. Their ablation is the headline: **relative offsets 83% vs 17% for absolute re-prediction**, lifting 0–14% one-shot models to 53–67% raw / up to 100% protocol success. For v2 this is the single highest-leverage grounding upgrade: a ~100-line wrapper that makes a *local* 2B grounder (ShowUI/MAI-UI class, fits the 2060) precise without any training. (Agent-S's ID-picking, formerly #3, moves to honorable mentions — excellent, but it needs an OCR-word pipeline v2 doesn't have yet; DVOC works with the pixel pipeline v2 already ships.)

**4. The 0–1000 display space + resize-aware rescale, as an explicit contract** — microsoft/fara `src/fara/agents/coord_spaces.py` + `fara15_agent.py:proc_coords/convert_resized_coords_to_original`; bytedance/UI-TARS-desktop `multimodal/gui-agent/action-parser/src/actionParser.ts:parseActionVlm`. Every serious vision CUA now emits coordinates in a normalized display space (Fara: 1000; Qwen3.5: **999** — the space is model-specific and must be a named constant), and the harness rescales through the *actual resized-image dimensions* (UI-TARS v1.5: Qwen-style `smartResize` factors instead of naïve /1000; NutJSOperator then applies the Retina `pixelDensity.scaleX/Y` a second time). Three stacked transforms — model space → resized image → logical screen → physical pixels — each owned by one function. v2's `pc.click` takes raw pixels; adopting the named-space + rescale chain is the cheapest accuracy upgrade available.

**5. LoopGuard: hashing-based loop/stagnation/cycle detection** — Jeomon/Windows-Use, `windows_use/agent/loop.py:LoopGuard`. SHA-256(tool + normalized params) over a 15-step window with escalating repetition nudges; desktop-state fingerprints (HWND + hash of interactive-elements string) detect stagnation (≥4 unchanged) and A→B→A cycles (visit counts); same-action-after-failure gets a targeted warning; warnings are injected into the next model step. ~150 lines of pure stdlib. v2's brain stops after 2 consecutive failures but is blind to cycles, stagnation, and repeat-success loops — this closes that hole wholesale.

**Honorable mentions:** **ID-picking grounding** — Agent-S s3 (`gui_agents/s3/agents/grounding.py:OSWorldACI`): OCR word boxes serialized as a word-id table, the LLM picks an *ID* (+ span alignment) and pixels come from the box, never from the model; paired with a separate grounding VLM whose bare coordinate answer is regex-extracted and linearly rescaled · **Actionability hit-test gates** — agent-desktop (`actionability/`): pre-click proof the target is visible, enabled, and actually receives events at that point (not occluded), plus snapshot-qualified refs that go stale loudly · **Recipes with preconditions + wait_after verification** — ghost-os (`Recipes/RecipeEngine.swift`): saved JSON workflows whose steps verify expected state materialized, with learn-by-watching (CGEvent tap, password keystrokes never recorded) as the acquisition path · **Rolling summarization + image budgets** — bytebot (`agent.processor.ts` + `summaries/`: token-threshold-triggered LLM summarization of the message tail, summaries as first-class stored rows), fara (`_fit_images_to_budget`: old screenshots evicted by token estimate), cua (`callbacks/image_retention.py`: keep only N most recent screenshot pairs; plus a budget-manager callback that hard-stops on cost, and an operator normalizer stripping hallucinated action keys pre-dispatch — pdagent's alias-repair, independently reinvented) — three implementations of one law: screenshots are the context bomb · UFO's **virtual UIA elements** — OmniParser detections are wrapped as `VirtualUIAElementInfo` (`ufo/automator/ui_control/grounding/basic.py`) so vision results and real UIA controls share one element type, one annotation pass, one action path · bytebotd's **daemon split** (all input/screenshot behind one HTTP service in a disposable Docker desktop; agent holds no OS privileges) · OS-Copilot's **self-growing tool library** (generated tools saved to `tool_repository/generated_tools`, vector-retrieved on later tasks) · e2b/open-computer-use's **structured self-check thought** ("On the screen, I see: … This means the objective is: [complete|not complete]. The next step is to [click|type|run] …") forced before every action.

## PER-REPO — HOW IT ACTUALLY WORKS (inside)

### trycua/cua (30,276★, ALIVE, MIT core) — the infrastructure play
Monorepo: `libs/cua-driver` (Rust/native driver, MCP-over-stdio), `libs/python/{agent,core,som}`, `libs/lume` (macOS VM), sandboxes/benchmarks. **Observation:** driver captures native window/desktop; optional `cua-perception` extension (OmniParser icon detector — **AGPL-3.0**, fenced off from the MIT driver) parses a retained capture into model-neutral text/icon regions. **Grounding→action binding:** a region-derived click must present the observation's one-use `capture_id` (mechanism 1). **Action:** background input — drives native macOS apps *without stealing focus*; SDKs (Python `cua_driver`, TS) call the same in-process runtime via UniFFI over a versioned C ABI; MCP is implemented by the executable only. **Agent loops:** `agent/cua_agent/agent.py:ComputerAgent` selects per-model loops (`loops/anthropic.py` 1,969 lines, `gemini.py`, `uitars.py`, `fara/`, `glm45v.py`…) over an `AsyncComputerHandler` protocol (`computers/base.py`: screenshot/click/type/drag/…); the anthropic loop proactively downscales screenshots past the API's internal downscale point and upscales returned coords by stored (scale_x, scale_y) — mismatched-scale clicks were a measured failure mode. **Verification:** new action-result contract (`docs/action-result-contract.md`): `effect ∈ {confirmed, partial, unverifiable, suspected_noop, refused}` + `escalation.target ∈ {pixel, foreground, page, session}` — the Wave-1 hermes verdict ladder, formalized; ambiguous `verified` boolean explicitly removed. **Safety:** permission modes fixed at launch — `standard` (promptless default), `bounded` (only tools/resources in a reviewed manifest), `unrestricted` (requires `--dangerously-bypass-approvals`; embedded launchers need env var + flag together); a YAML/Rego policy engine is the ceiling in *every* mode ("a mode can never turn a policy denial into an allow"); consent via protected channel; grants visible + revocable; daemon fails closed on policy errors. Plus callbacks: budget hard-stop, PII anonymization of screenshots, trajectory saver. **License: MIT (driver/agent) — steal YES, incl. the capture-binding design.**

### bytedance/UI-TARS-desktop (39,340★, ALIVE, Apache-2.0) — the productized stack
pnpm monorepo; the GUI agent lives in `multimodal/gui-agent` (agent-sdk, action-parser, operators) on the `multimodal/tarko` agent framework. **Loop:** `agent-sdk/src/GUIAgent.ts` wraps a Tarko agent with `maxLoopCount → maxIterations`; hooks take a screenshot after every tool call (`onAfterToolCall`) — observation is post-action by construction. **Grounding:** `action-parser/src/actionParser.ts:parseActionVlm` parses the UI-TARS text protocol (`Thought:`/`Reflection:`/`Action_Summary:`/`Action:` blocks, plus an o1 XML variant and `<computer_env>` blocks); `start_box` coords are divided by `factors` (default [1000,1000]; for V1.5, `smartResizeForV15` factors from the Qwen smart-resize of the actual screenshot), box center × screen dims × `scaleFactor` → pixels. **Operators:** nut.js (desktop: `operator-nutjs/src/NutJSOperator.ts` — screen context caches logical size = physical / pixelDensity), browser, ADB, AIO sandbox — one agent, four desktops. **Safety:** loop caps + operator-level only; no approval layer in the SDK path. **Steal: the action-parser's three-transform discipline and the multi-operator abstraction (Apache-2.0, ideas+code with attribution).**

### microsoft/OmniParser (25,533★, ALIVE, code CC-BY-4.0 per repo LICENSE / model weights under separate terms — attribution required)
`util/omniparser.py:Omniparser.parse` → `util/utils.py:get_som_labeled_img` + `check_ocr_box`. **Pipeline:** EasyOCR (text_threshold 0.8) or PaddleOCR → text boxes; a fine-tuned YOLO icon detector runs at a very low box threshold (config `BOX_TRESHOLD`≈0.05, NMS IoU 0.1); `remove_overlap_new(boxes, iou_threshold≈0.7, ocr_bbox)`: when two icon boxes overlap, the *larger* is dropped (tighter box wins); an icon fully inside an OCR text box is dropped (text already describes it); surviving icons are cropped and captioned in batches (Florence-2 default caption model; BLIP-2 legacy) → SOM image with numbered boxes + `parsed_content_list[{id, type: text|icon, bbox (ratio coords), content}]`. **Consumers:** `omnitool/` (Gradio + server) wires it to GPT-4o/Claude/DeepSeek as the eyes of a planner. **Weakness (from code):** pure function of the frame — no temporal filtering, so caption flicker between frames is passed straight to the planner; thresholds are global constants, not per-app. **Steal: YES — the merge discipline (OCR wins over icons inside it; tighter box wins overlaps) is ~40 lines of pure logic on top of any detector; v2's planned OCR fallback should adopt it wholesale.**

### simular-ai/Agent-S (12,657★, ALIVE, Apache-2.0) — Agent S3
`gui_agents/s3/`: `agents/worker.py` (executes one subtask as generated Python against the ACI), `agents/code_agent.py` (delegated non-GUI subtasks: files/shell), `agents/grounding.py:OSWorldACI`, `bbon/` (behavior narrator + comparative judge — behavior-level best-of-n), `memory/procedural_memory.py`. **Flow:** manager plans subtasks → worker emits code calling `aci.click("Settings icon")` → grounding resolves the description at call time (mechanism 3). `click/type/drag` all funnel through `resize_coordinates`. `set_cell_values` writes spreadsheets through app scripting instead of keystrokes — a "prefer the app's own API over pixels" escape hatch used mid-task. **Verification:** the worker's code can assert on `aci` return states; BBON narrates candidate trajectories and a judge picks — verification by comparison, expensive but real. **Safety:** runs against OSWorld VM by default; no in-loop approval (research code). **Steal: ID-picking text grounding (stdlib-shaped: OCR word boxes + ID table) — the single most portable grounding trick in this wave for a UIA-first system whose tree sometimes lacks text.**

### microsoft/UFO (10,075★, ALIVE, MIT) — UFO²/UFO³, the Windows-native elder
`ufo/agents/` (HostAgent selects the app, AppAgent works it; Galaxy = multi-device constellation in v3), `ufo/automator/ui_control/` (`inspector.py`, `controller.py`, `control_filter.py`, `grounding/`), `ufo/automator/app_apis/` (COM/API automation for Office apps + shell client). **Observation:** UIA tree via pywinauto `UIAWrapper` with cached property fetching (`UIABackendStrategy._get_cache_request`) — built because naive UIA walks are too slow for an agent loop. **Filtering:** mechanism 2. **Grounding:** hybrid — annotated screenshot + filtered control list; the model picks a control **by index**; `grounding/omniparser.py:OmniparserGrounding._calculate_absolute_coordinates` converts OmniParser relative boxes to absolute using the target app's UIA rect; detections become `VirtualUIAElementInfo` so one code path acts on both. **Action:** `controller.py` invokes UIA patterns (Invoke/ValuePattern/…) first, pyautogui fallback. **Safety:** config-level `SAFE_MODE`-style confirmations existed in UFO² for destructive ops (prompt-based, not structural); the app-API layer can run shell — gated by config only. **Steal: YES — control filtering + virtual-element unification are the two designs v2's `pc_control.py` most lacks (MIT).**

### microsoft/fara (6,221★, ALIVE, MIT) — Fara-1.5, Microsoft's CUA model + reference agent
`src/fara/agents/fara/fara15_agent.py` (841 lines) over a Playwright browser environment (`environments/playwright/`) — despite the "computer use" name, this release is web-only. **Grounding:** model emits coords in the normalized display space (`agents/coord_spaces.py`: FARA 1000 / QWEN35 999) → `convert_resized_coords_to_original` rescales via resized-vs-original dims. **Parsing:** `<tool_call>\n{json}\n</tool_call>` with `ast.literal_eval` fallback for malformed JSON; `terminate_on_parse_error` config decides whether a parse failure kills the run or raises. **Retry:** `tenacity` on the model call — exponential backoff (×5, 5–60 s, 5 attempts) but *never* retries `BadRequestError`: the retryable/non-retryable split made explicit. **Safety = "critical points"** (`agents/fara/_prompts.py:build_fara_fn_call_template`): a registry of named policies injected into the system prompt — pause and ask when (1) required info is missing, (2) the task is ambiguous, OR (3) an irreversible action is next. Prompt-level, model-enforced — weaker than v2's gate, but the *taxonomy* (missing/ambiguous/irreversible) is exactly the tier-2 trigger list, written by Microsoft's own team. **Context:** `_fit_images_to_budget` evicts old screenshots by token estimate. **Steal: the critical-points taxonomy as gate copy, and the 999-vs-1000 warning — never hardcode the coordinate space.**

### bytebot-ai/bytebot (11,070★, ALIVE, Apache-2.0) — isolation-by-container
Two services: `packages/bytebotd` (NestJS daemon *inside* a Docker Linux desktop: nut.js input + `screendump` screenshots, `computer-use.service.ts:action` switch; app control via `wmctrl` exec'd as the desktop user; built-in file read/write actions) and `packages/bytebot-agent` (task loop; per-model services for Anthropic/OpenAI/Google; messages persisted via Prisma/Postgres). **Flow:** user task → agent calls daemon HTTP actions → screenshot returns base64 → next step. **Memory:** mechanism 5 — token-threshold rolling summarization (`agent.processor.ts:233ff`); summaries stored as first-class rows, unsummarized tail re-attached after the latest summary. **Verification:** none beyond the next screenshot (the model judges). **Safety:** the container *is* the safety story — disposable desktop, agent process holds no host privileges; in-loop there are DTO validation pipes but no confirmations. **Steal: the daemon split maps cleanly onto v2's tiering (a dumb, auditable executor process behind HTTP, brain elsewhere) — and rolling summarization for long GUI sessions.**

### OthersideAI/self-operating-computer (10,291★, ALIVE, MIT) — the 2023 ancestor
`operate/operate.py:main/operate` loop; `operate/models/apis.py` (~1,100 lines of per-model adapters); `operate/utils/{ocr.py,label.py,operating_system.py}`. **Three grounding modes**, switchable per model: (1) direct coordinates from GPT-4V; (2) **OCR mode** — EasyOCR enumerates text elements, boxes are drawn and numbered on the image, the model replies with an element *index*, `ocr.py:get_text_element` maps index → center; (3) **labeled mode** — a bundled YOLO model (`operate/models/weights`) detects UI elements, `label.py:add_labels` draws numbered labels (with overlap suppression in `is_overlapping`), model picks a label, `get_label_coordinates` resolves it; `get_click_position_in_percent` converts to screen %. This repo *invented* the index-picking pattern Agent-S later refined. **Action:** pyautogui via `operating_system.py`; actions parsed from JSON in free-text replies (`clean_json`). **Safety:** none — 2023 research demo; it types what the model says. **Steal: historical priority only; take Agent-S's version of the pattern instead.**

### OS-Copilot/OS-Copilot (1,795★, ALIVE, MIT) — FRIDAY: the tool-synthesizer
Not a click agent: `oscopilot/modules/planner/friday_planner.py` decomposes the task; `modules/executor/friday_executor.py:FridayExecutor.generate_tool` asks the LLM to *write* a tool (Python / Shell / AppleScript) for each subtask, runs it in `environments/` (subprocess, bash, Jupyter, AppleScript), `max_iter=3`, wrapped in `api_exception_mechanism(max_retries=3)`. Successful tools persist into `oscopilot/tool_repository/generated_tools/` and are re-found by `modules/retriever/vector_retriever.py`; `agents/self_learning.py` + `modules/learner/self_learner.py` close the loop. **GUI relevance:** apps are driven through their CLIs/APIs/scripts — the "no pixels at all" end of the spectrum, and a standing reminder that many "GUI tasks" have a scriptable back door (UFO's app_apis make the same bet). **Safety:** generated code executes after LLM self-review prompts only — the MAL19 pattern (Wave 1) with better manners; v2's sandbox rules must not soften because the framing is friendlier. **Steal: the tool-library-with-retrieval shape — v2's skill quarantine + approval is exactly the gate this design lacks; combining them (generated skill → quarantine → approve → library) is a roadmap item, not a copy.**

### e2b-dev/open-computer-use (2,376★, ALIVE, Apache-2.0) — small, readable, instructive
`os_computer_use/sandbox_agent.py:SandboxAgent` — tools are Python methods auto-registered by a `@tool(description, params)` decorator. **Flow:** `run()` forces a structured vision pass before each action (`append_screenshot` prompt: "The objective is: … On the screen, I see: [extensive list] … This means the objective is: [complete|not complete] … The next step is to [click|type|run the shell command] …"). **Grounding is outsourced and element-first:** `click(query)` takes *text*, `click_element` screenshots → `grounding_model.call(query, screenshot)` (OS-Atlas HF endpoint `osatlas_provider.py`, or `showui_provider.py`) → `grounding.py:extract_bbox_midpoint` parses `<|box_start|>…<|box_end|>` special-token output (2 numbers = point; ≥4 = box midpoint) → draws a big red dot on the screenshot and saves it as the audit image before clicking. **Environment:** E2B desktop sandbox; `sandbox.set_timeout(60)` refreshed each iteration to keep the VM alive. **Safety:** VM isolation only. **Steal: the special-token bbox-midpoint parser (10 lines) and the forced perception-narration format — a cheap verifier scaffold for v2's post-action screenshots.**

### TurixAI/TuriX-CUA (3,173★, ALIVE, MIT) — AX-native macOS agent
`src/agent/service.py` (planner + memory), `src/mac/{tree.py,element.py,actions.py}` — full ApplicationServices binding: the AX tree is walked natively (`AXUIElementCreateApplication`, children/role/position attributes), `MacElementNode` wraps each element (role, actions list, enabled, position, size). **Observation for the model:** `element.py` serializes *visible clickable elements* into an indented string with two formats — short (token-cheap) and original — chosen with an explicit token estimator (`count_tokens`, ~3 chars/token) in `_get_visible_clickable_elements_string`. **Action:** `AXUIElementPerformAction(kAXPressAction)` / `AXUIElementSetAttributeValue` — real accessibility actions, pixel fallback in `mac/actions.py`. **Memory:** service keeps a summarized "brain memory" with per-entry normalization, a 50-entry index in-prompt, and summary-validity checks (`_is_summary_valid`) — summarization with a seatbelt. **Safety:** none structural (research release). **Steal: token-budgeted tree serialization — v2's UIA dump needs the same two-format (full/short) treatment before long Windows trees blow the prompt.**

### mediar-ai/terminator (1,657★, ALIVE, MIT) — "Playwright for Windows", the selector engine
Rust workspace; core crate `crates/terminator/src` (~28k lines): `platforms/windows/engine.rs` (4,136 lines, UIA), `selector.rs`, `locator.rs`, `tree_formatter.rs`, `ui_tree_diff.rs`, plus `crates/terminator-computer-use` (agent-facing tools) and an MCP agent crate. **The selector algebra is the contribution:** `Selector` enum — Role+name, AutomationId (`NativeId`), Name, Text, XPath-like `Path`, Attributes map, ClassName, Process, **spatial relations** (`RightOf/LeftOf/Above/Below/Near(anchor)`), `Nth`, Playwright-style `Has(descendant)` and `Parent`, and boolean `And/Or/Not` combinators, with a string parser (boolean-expression tokenizer). **Locators wait properly:** `locator.rs` — default timeout 0 (one-shot), explicit waits poll `find_elements`; actions can capture a **UI-tree diff** (`ui_tree_diff.rs:simple_ui_tree_diff` over compact YAML with ids/bounds stripped) before/after execution — structural effect verification instead of screenshot-guessing. An on-screen action overlay highlights the element being acted on (user transparency). **Steal: the spatial/boolean selector vocabulary and tree-diff verification — both pure logic, both directly applicable to v2's UIA tree (MIT).**

### Jeomon/Windows-Use (473★, ALIVE, MIT) — small Python Windows agent with a big idea
`windows_use/agent/`: LangChain-style agent over a `Desktop` service; `agent/tree/service.py:Tree` walks UIA via the `uiautomation` COM package using Cached* properties, then `_dom_correction` *rewrites* the raw tree into an LLM DOM (group controls collapsed, only whitelisted interactive control types surfaced, window-relative IoU bounding boxes) — tree hygiene as a first-class pass. **The standout is `agent/loop.py:LoopGuard`** (mechanism-grade): every action is SHA-256-hashed (tool + normalized params, volatile params ignored) into a 15-step window — repetition thresholds trigger escalating nudge strings; desktop state is fingerprinted as (HWND, hash of the interactive-elements string) — ≥4 identical consecutive states = stagnation warning; a visit-count map catches A→B→A cycles the consecutive check can't; the *same action retried immediately after failing* gets its own targeted warning. `check()` runs before each LLM step and injects warnings into context. Also a UIA focus-change watchdog (`on_focus_change`). **Safety:** warnings only — the model can ignore them; no gate. **Steal: YES, immediately — LoopGuard is ~150 lines of stdlib (hashlib/json/collections) and closes v2's biggest loop-reliability hole: v2 stops after 2 failures but cannot see cycles or stagnation at all.**

### agent-sh/computer-use-linux (716★, ALIVE, MIT) — AT-SPI with adult supervision
Rust; `src/atspi_tree.rs` builds semantic trees over the AT-SPI D-Bus bridge; input via ydotool (`src/ydotool.rs`, uinput-level) and an absolute-pointer path; MCP + CLI surfaces. **Snapshot discipline, hard-coded:** default max 1,000 nodes (hard 2,000), depth 32 (hard 64), 10-second snapshot deadline, text readback capped at 4,096 chars / 8 selections, discovery roots capped at 256. **The `accessibility_guard.rs` principle:** GNOME's `toolkit-accessibility` setting is flipped only by an explicit, foreground, user-visible "hold-open" — its doc comment states it is *never started by observation tools*. Observation must not mutate the system to observe it. **Actions:** AT-SPI Action interface first (`do_action` by index), coordinate fallback for apps with no a11y (xterm/Electron gaps are named in code). **Steal: the snapshot caps + deadline as constants in v2's `pc.observe`, and the guard principle verbatim for any future "enable accessibility" flow.**

### showlab/computer_use_ootb (1,972★, ALIVE, Apache-2.0) — planner/actor split, local grounder
ShowUI's official "out-of-the-box" app: `computer_use_demo/loop.py:sampling_loop_sync` hosts pluggable planners (`gui_agent/planner/`: Anthropic agent, API-VLM planner, local-VLM planner) and actors (`gui_agent/actor/showui_agent.py:ShowUIActor`, `uitars_agent.py`). The actor is a **local** ShowUI-2B (Qwen2-VL) that receives (instruction, screenshot, action history) and emits exactly one action dict `{'action','value','position'}` with position in **0–1 relative** space and per-surface action maps (desktop: CLICK/INPUT/HOVER/ENTER/SCROLL/ESC/PRESS; phone: TAP/SWIPE/…). Execution via pyautogui in `executor/`; `tools/` vendors Anthropic's computer-use tool collection (computer/bash/edit). **Design lesson:** separating the expensive planner from a cheap, local, single-step grounder is what makes the loop affordable — and the 0–1 space is yet another coordinate convention (cf. fara's 1000, Qwen's 999) reinforcing mechanism 4's warning. **Steal: the planner/actor cost split as an architecture option for v2's local-model mode (2060: small local grounder + cloud planner).**

### ghostwright/ghost-os (ALIVE, MIT) — macOS MCP server; recipes + learn-by-watching

### Pomilon-Intelligence-Lab/DVOC (ALIVE, MIT) — damped visual offset correction: weak VLMs, pixel-precise grounding
A training-free **iterative grounding refinement protocol** (paper + artifacts in-repo, `PAPER.md`). One-shot absolute prediction is replaced by a closed kinematic loop: (1) render the current estimate onto the screenshot as a **crosshair + blue uncertainty circle (3px, fixed 30px radius)**; (2) the VLM — shown the annotated image plus its own iteration history — answers with a *relative* correction via `report_offset(dx, dy, confidence)`; (3) the corrector applies the offset under **exponential damping α(0)=1.0, α(1)=0.5, α(≥2)=0.25**; repeat. **Stop rules:** ACT_SAFE when error < ε (30px) and confidence ≥ 0.5 for **2 consecutive** iterations; ABORT_OSCILLATION when error is non-decreasing for 3+ iterations; hard cap 15. **Results (their benchmark, 4 VLMs × 11 tasks, 463 trials):** naive one-shot 0–14% (models fixate on wrong points at self-reported confidence 1.0); DVOC 53–67% raw / 63–100% protocol convergence, 4–10 iterations typical, a 26B model at 100% protocol. **The decisive ablation: relative-offset parameterisation 83% vs 17% for absolute re-prediction** — asking "how far off is the marker?" is a categorically easier visual task than "where is the target?". Caveat: the benchmark's stop rule uses true distance; in production the proxy is offset magnitude + confidence, so expect some discount. **Steal: YES — top-tier for v2's hardware. DVOC is a wrapper, not a model: any weak local grounder (ShowUI-2B / MAI-UI-2B on the 2060) becomes precise at the cost of ~5 extra *local* calls, zero training, ~100 lines. It converts v2's grounding problem from "buy a better model" into "run the loop".**

**The wave's five convergent laws** (independent codebases arriving at the same design):
1. **Never let the model invent pixels when a structure can name the target** — UIA/AX element indices (Qwen OCC, terminator, TuriX), OCR word-ids (Agent-S), DOM ids (ghost-os), snapshot refs (agent-desktop). Raw-coordinate clicking is the fallback, not the path.
2. **Coordinate spaces are named per-model contracts** — 1000 (Fara/UI-TARS), **999** (Fara-Qwen3.5 profile, EvoCUA S2, MAI-UI SCALE_FACTOR), 0–1 (ShowUI), smart-resize absolute (UI-TARS S1-style) — with the rescale chain owned by exactly one function. 3. **Verification is a return type, not a hope** — cua's effect enum, agent-desktop's delivered_unverified/delivered_verified + hit-test gates, ghost-os's wait_after ("action succeeded but expected state didn't materialize" as a distinct error), ScreenAgent/Cradle's named evaluation phases.
